# Open ALO Studio

Studio is a dependency-free local web UI for writing, validating, visualizing,
and running ALO documents. Launch it from the repository with:

```bash
alo studio
```

The default bind address is `127.0.0.1`. Use `--port 0` (the default) to let
the operating system choose a free port, or pass `--no-browser` when the
browser should not open automatically.

## API

All request bodies are JSON objects. Malformed bodies return HTTP 400 with
`{"errors": ["..."]}`. ALO parse and validation failures return HTTP 200 with
the same error-only shape, except `/api/validate`, which always returns its
`valid` and `errors` fields.

`GET /api/examples`

Returns an array containing the bundled example files:

```json
[
  {"id": "minimal", "path": "examples/minimal/alo.yaml", "source": "..."}
]
```

`POST /api/validate`

Request: `{"source": "<YAML or JSON text>"}`

Response: `{"valid": true, "errors": []}` or
`{"valid": false, "errors": ["..."]}`.

`POST /api/graph`

Request: `{"source": "<YAML or JSON text>", "direction": "TD"}`;
`direction` is optional and supports the Mermaid directions `TB`, `TD`, `BT`,
`LR`, and `RL`.

Success response:

```json
{"graph": {"graph_ir_version": "0.1", "source": {}, "nodes": [], "edges": []}, "mermaid": "...", "svg": "<svg ...>...</svg>"}
```

For a canonical (`spec_version: "0.2"`) document, `graph` is instead the
Object Graph IR (`object_graph_ir_version`, `MAIN_OBJECT`/`SUB_OBJECT`/
`STATE`/`MANAGER`/`INPUT`/`OUTPUT` nodes, plus any `JEV_NOUL`/`JEV_CHOICE`/
`JEV_SCORE` overlay nodes) -- see docs/spec.md and
docs/complete-implementation-guide.md. `/api/graph` dispatches on the
document's own `spec_version`; the caller does not choose.

`POST /api/prompt`

Canonical documents only (`spec_version: "0.2"`). Request:
`{"source": "<YAML or JSON text>"}`. Success:
`{"prompt": "<rendered ALO Prompt text>"}` -- the mainObj/subObjList/
State/managerObj sections from `packages.compiler.render_prompt`. A
legacy (`0.1`) document returns `{"errors": [...]}`.

`POST /api/run`

Request: `{"source": "<YAML or JSON text>", "input": {}, "responses": {}}`.
Both object fields default to `{}`. Success returns the Run Record JSON
directly -- the Draft 0.1 shape (`state_after`/`output`) for a legacy
document, or the canonical Draft 0.2 shape (`State_after`/`manager_trace`/
`jev_calls`/`output`) for a canonical one, dispatched the same way as
`/api/graph`. `/api/run` uses only `MockDecisionProvider` today by design:
the no-login local mode works without a network connection or API key.

The Studio's import file control uses the browser `FileReader` API, and its
Download button uses a client-side `Blob`; neither operation writes to the
server filesystem. The graph viewer uses the SVG generated by Python and has
no external JavaScript, framework, stylesheet, or CDN dependency.

`POST /api/assist` (optional)

Request: `{"description": "<plain-language workflow description>", "model": "<model name>", "api_key": "<optional>", "base_url": "<optional, default https://api.openai.com/v1>"}`.

This route is entirely optional and is the only one that ever talks to a
network endpoint. It requires the caller to supply their own `model` (and
usually `api_key`/`base_url`) for an OpenAI Chat Completions-compatible
service. The key is forwarded only to the endpoint you configure, for that
one request, and Studio never stores or logs it. `/api/validate`, `/api/graph`,
and `/api/run` never require this route or any API key — the no-login local
mode stays fully offline by default.

A missing `description` or `model` returns HTTP 400. Otherwise the response
is `{"source": "<generated ALO YAML>", "valid": true|false, "errors": [...]}`
— the draft is returned together with its own validation errors, if any, so
an imperfect draft is still useful as a starting point. A provider-level
failure (bad key, unreachable endpoint, malformed response, etc.) returns
HTTP 200 with `{"errors": ["..."]}` and no `source`.
